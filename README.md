# eap-rag · 一线管理者的「困难对话」教练

管理者发现下属状态不对时（绩效下滑、突然沉默、情绪崩溃、疑似抑郁），
系统给出**有出处、有边界、可执行**的谈话准备：判断要点 → 对话剧本 → 边界提示 → 转介路径，
每条建议都能展开到 WHO / NIOSH 的原文段落。

> 管理者输入：「我组里一个平时很靠谱的同事，这两周突然不说话了，问他只回『没事』，绩效掉了。我该怎么谈？」
>
> 系统输出：三句话判断 + 开场白 ×3 + 开放式问题 ×5 +「三种反应怎么接」+ 转介条件，
> 并明确写出「不要承诺保密」「不要做诊断」。
>
> 输入换成「他昨天说活着没意思」→ **不再生成剧本**，直接走危机流程与热线。

## 仓库里现在有什么

`src/rag/` 是 Week 0 的**检索原型**：入库 → 切块 → 向量化 → SQLite 检索 → 生成。
它验证了链路，也留下了可复用的切块与存储逻辑；正式实现会迁移到 `apps/api`。

```bash
make test                 # 14 个单元测试
make demo                 # 入库示例文档 + 离线回答
make ingest               # data/raw → 索引
make ask Q="文档怎么切块？"
```

原型默认用哈希嵌入（离线、确定性）和本地 Qwen（`:8000` OpenAI 兼容）——
真嵌入与云端 LLM 在正式实现里替换，接口不变。

## 边界

这是**参考实现与作品集项目**，不是可上线的 EAP 服务：
不做诊断、不做治疗、不做危机干预本身；公开演示必须保留免责声明与危机资源；
语料许可（WHO 非商业条款）在商业化前需重新评估。
