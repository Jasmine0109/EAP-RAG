# eap-rag 项目文档 v0.2 —— 大框架 + MVP

> 一句话：一个面向所有人的「职场心理与生活支持」助手，聊天式问答，答案带出处。
> 状态：方向已定；MVP 定义完成，准备搭建。
> 本文档取代 v0.1（998 行详细版）；详细设计推迟到 V1/V2，老版本仍在 git 历史里可查。

## 1. 项目是什么

**一句话**：任何人打开一个网页，把困扰说出来（压力大、升职卡住、和老板/同事处不好、焦虑、失眠……），系统从知识库里找到对应的科普、自助方法和公司政策，给出一段有出处的回答。

| 维度 | 内容 |
| --- | --- |
| 给谁 | 所有人（员工），不区分角色，不需要登录 |
| 解决什么 | 职场压力 / 关系 / 晋升 / 情绪（焦虑、抑郁情绪、失眠）的「我该怎么办」+ 公司政策与福利 |
| 怎么用 | 打开网页 → 聊天 → 得到带来源的答案 |

## 2. 它不是什么（红线）

- 不诊断、不开药、不给治疗建议、不替代心理咨询。
- 危机（自伤 / 轻生）只给热线和求助路径，不给别的。
- 不提供真实的医疗或法律建议。

## 3. 最小 MVP

**目标：本地跑通一个 UI，员工能问、能拿到有出处的答案。** 具体长什么样、怎么交互，见 [MVP 设计](MVP-设计.md)。

组成（5 块）：

1. **聊天 UI**：一个网页，输入问题、显示答案，答案里的来源可点开看原文。
2. **知识库**：从白名单源抓下来的内容，清洗后切块、向量化、存库。
3. **检索**：把问题变成向量，从库里找最相关片段。
4. **生成**：片段 + 问题 → LLM → 带出处的回答。
5. **安全底线**：危机词 → 只回热线，不做别的。

**MVP 不做**（全部往后放）：登录、角色权限、后台看板、token 统计、评测平台、云端部署、多语言、多轮记忆、复杂安全分类器。

## 4. 一页大框架

| 阶段 | 做什么 | 验收 |
| --- | --- | --- |
| MVP | UI + 知识库 + 检索 + 生成 + 危机一条线（本地） | 能问、能拿到带出处答案 |
| V1 | 知识库补全 + 30 条评测用例 | 能回答「做得好不好」 |
| V2 | 后台看板 + 评测对比 embedding/LLM + 云端公开部署 | 有 URL、有指标、有模型选型依据 |
| V3 | 危机识别增强、多轮记忆、更多语料 | —— |

## 5. 数据从哪来（pipeline）

按你的要求「从网上爬数据」。做法是**白名单爬取 pipeline**，不是全网乱爬：

```
白名单源清单 → 抓取 → 解析(去 HTML) → 清洗(去导航/广告/重复) → 切块 → 向量化 → 入库
```

为什么白名单：① 质量可控（科普必须权威，不能是营销号）② 版权可控（标注来源与许可）③ 尊重 robots.txt。

候选源（MVP 先取其中 3–5 个，逐个验证「可爬 + 许可」）：

| 类别 | 候选源 |
| --- | --- |
| 职场压力 / 倦怠 | NIOSH / OSHA（公有领域，英文）、WHO 中文资料 |
| 情绪科普（焦虑 / 抑郁情绪 / 失眠） | 国家卫健委 / 中国疾控精神卫生科普、三甲医院精神心理科官网科普、中科院心理所科普 |
| 危机资源 | 心理援助热线公开信息（用于安全底线） |
| 公司政策 / 福利 | 通用「职工心理健康 / EAP」公开资料（人社 / 工会公开文件、公开 EAP 案例），**标注为通用参考，不是真实公司政策** |

> 每条入库内容都记录：来源 URL、抓取时间、许可、标题。爬取遵守 robots.txt，不收录版权敏感内容。

## 6. MVP 技术骨架（一页，不写 LLD）

| 块 | 用什么 | 备注 |
| --- | --- | --- |
| UI | 最简单的单页 HTML + 聊天框（FastAPI 直接 serve），跑通后再换正式前端 | 先能点、能答 |
| 后端 | Python FastAPI | 一个 `/api/chat` 接口 |
| 知识库 | SQLite（本地）+ 向量 | Week 0 原型已有切块/入库代码可复用 |
| 嵌入 | 有 torch/sentence-transformers 就用 bge-small-zh，否则先哈希占位 | MVP 期间定 |
| 生成 | 本地 Qwen（`:8000` OpenAI 兼容），云端换 DeepSeek | 只改配置 |
| 安全 | 一条危机词规则 | 命中 → 热线模板 |

## 7. 安全底线（3 行）

- 出现「不想活 / 自伤 / 结束生命 / 解脱」等词 → 不检索不生成，只给热线 + 求助路径。
- 问「我是不是抑郁 / 焦虑症」→ 说「不能诊断」，给科普 + 建议求助。
- 这是代码分支，不是提示词。

## 8. 里程碑（搭 MVP 的顺序）

1. 数据 pipeline：白名单源 + 抓取脚本 + 清洗 + 入库（先跑通 3 个源）
2. 检索 + 生成：问答链路先在命令行跑通
3. UI：单页聊天，接上 `/api/chat`
4. 安全底线 + 引用标注
5. 本地整体跑通 → 你来试用、提问题
