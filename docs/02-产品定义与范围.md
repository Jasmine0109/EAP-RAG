# 02 · 产品定义与范围

> 项目代号：**eap-rag** · 一线管理者的「困难对话」教练
> 状态：设计定稿，待进入 Week 1 实现

## 一句话

给没有心理学背景的管理者，在发现下属「状态不对」时，提供一份**有出处、有边界、可执行**的 15 分钟谈话准备。

## 用户与场景

| 项 | 内容 |
| --- | --- |
| 主用户 | 带 5–15 人团队的一线 / 中层管理者，非心理学背景 |
| 触发时刻 | 绩效突然下滑、开会不说话、频繁请假/旷工、情绪爆发、同事冲突、疑似抑郁焦虑、裁员或组织调整沟通 |
| 现有替代 | 问 HR（慢、怕留痕）、问通用 AI（不懂边界、可能给诊断）、自己硬谈（最容易踩雷） |
| 核心焦虑 | 「我说错话会不会把他推向更糟？我是不是越界了？这事该不该上报？」 |

## 一次交互交付什么

不是一段散文，而是一份**结构化行动卡**：

1. **判断三句话**：现在该做的、千万别做的、什么时候必须停。
2. **谈话剧本**：开场白 ×3（按关系远近）→ 开放式问题 ×5 → 三种反应（哭 / 否认 / 愤怒）的回应。
3. **边界提示**：不诊断、不承诺保密、不站队、不当「半个咨询师」。
4. **转介路径**：EAP 联系方式、危机资源、什么时点拉 HR 进来。
5. **出处**：每条建议可展开到原文段落（WHO / NIOSH / NVC 框架 / 心理安全感）。
6. **收尾动作**：记录什么、48 小时回访、升级条件。

## 明确不做（v1）

- 不做员工自测、不做诊断、不评估「有没有病」。
- 不给治疗建议、不给药物信息、不做危机干预本身（只做识别 + 转介）。
- 不帮管理者「让员工主动离职」「收集证据」「监控情绪」。
- 不做组织层面的心理健康报表（后续版本再谈，且必须匿名聚合）。

## 安全红线（写进代码，不靠 prompt 祈祷）

| 触发 | 系统行为 |
| --- | --- |
| 自伤 / 自杀 / 伤人信号 | **熔断**：跳过知识库与剧本生成，输出危机响应流程 + 24h 热线，提示立即联系 EAP/急救 |
| 「他是不是抑郁症/精神病？」 | 拒答 + 解释：诊断只能由有资质者在面谈中做出 |
| 用于惩罚、解雇、劝退、监控 | 拒答 + 合规提示（可能构成歧视或违法解除风险） |
| 未成年人、家暴、法律纠纷 | 超出范围，转介专业人士 |

## 成功标准（上线前必须全部达标）

| 维度 | 指标 | 目标 |
| --- | --- | --- |
| 敢用 | 20 名管理者试用后「我准备好谈了」自评（1–5） | ≥ 4.0 |
| 可信 | 引用支撑率（每条引用能在原文找到依据） | ≥ 95% |
| 安全 | 危机用例转介召回 | **100%** |
| 安全 | 越权/诊断类请求拒答正确率 | **100%** |
| 体验 | 首字延迟 p95 / 完整回答 p95 | ≤ 1.5s / ≤ 4s |
| 成本 | 单次对话成本 | ≤ $0.003 |

## 演示叙事（30 秒能讲清）

> 管理者输入：「我组里一个平时很靠谱的同事，这两周突然不说话了，问他只回『没事』，绩效掉了。我该怎么谈？」
>
> 系统返回：三句判断 → 开场白 → 5 个开放式问题 →「他说没事时怎么接」→「他说撑不住时怎么转介」→
> 每条带 WHO / NIOSH 原文出处，并明确写着「不要承诺保密」。
>
> 换一个输入：「他昨天说活着没意思」→ 系统**不再给剧本**，直接给危机流程和热线。

## 为什么这个切口适合作为 RAG 项目

1. **语料是公开且权威的**（WHO、NIOSH 属公有领域/开放许可），没有版权雷区。
2. **答案有金标**：场景 → 该检索哪一节 → 该不该转介，都可人工判定。
3. **硬边界天然存在**：诊断、保密、危机，正好练「检索到了也必须不回答」。
4. **管理者的真实痛点**不是「知道概念」，而是「下一句说什么」——这正是检索 + 生成能兑现的价值。
