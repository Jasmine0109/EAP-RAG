# 架构决策记录（ADR）

骨架阶段只记录"为什么这么选"，不记录实现细节。新增决策追加在末尾。

## ADR-0001 只用 numpy，不引框架

**决定**：不引入 LangChain / LlamaIndex，不引入向量数据库。

**理由**：骨架的价值在于**链路透明**。框架会把切块、检索、prompt 藏进几十层
默认值，出问题时无从下手。450 行 Python 能跑通同样的事，且每个环节可单独替换。

**代价**：没有现成的连接器、没有增量索引、没有多路召回。等需求明确再引，
届时替换点已经预留好（`Embedder` / `Store` / `LLMClient`）。

## ADR-0002 默认嵌入用特征哈希

**决定**：`HashingEmbedder`：词 + 中文相邻二元组，blake2b 散列到固定维度，带符号、L2 归一。

**理由**：零下载、零网络、确定性（同输入永远同向量，便于测试和增量重建）。
它的检索能力接近关键词匹配，足以验证"入库 → 检索 → 生成"是否通。

**代价**：同义改写召回不了。**这是已知且有意接受的**，换真模型是第一步升级。

## ADR-0003 存储用 SQLite + 暴力余弦

**决定**：单文件 SQLite，向量以 float32 BLOB 存 `vectors` 表，检索时全量矩阵乘。

**理由**：几万块以内，一次 `V @ q` 是毫秒级，比维护向量库进程便宜得多；
单文件拷贝即可搬家。SQLite 自带事务，`replace_doc` 天然幂等。

**代价**：十万块以上线性变慢；没有 HNSW 近似检索。届时换 sqlite-vec 或 FAISS，
`Store` 接口不变。

## ADR-0004 生成走 OpenAI 兼容协议

**决定**：`POST {base_url}/chat/completions`，用标准库 urllib，失败时退回离线片段。

**理由**：llama.cpp、MLX、Ollama、vLLM 都实现这套协议，一处适配处处可用；
失败兜底保证"LLM 没开也能查文档"，不会因为模型挂掉整条链路不可用。

**代价**：拿不到流式输出和 token 统计。需要时再升级，接口只要求 `chat() -> str`。

## ADR-0005 切块以"不超长"优先于"重叠"

**决定**：按空行分段 + 贪心拼接，块长严格 ≤ `chunk_size`；尾部重叠放得下才带，
放不下就放弃。

**理由**：超长块会撑爆上下文、稀释相似度；重叠只是缓解边界效应，可以牺牲。
规则简单到能用三个测试锁死（不超长、能重叠、超长段落硬切）。

**代价**：极端情况下相邻块没有重叠，边界处的句子可能被切散。
