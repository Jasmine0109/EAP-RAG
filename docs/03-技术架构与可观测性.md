# 03 · 技术架构与可观测性

## 总览

```
                    ┌──────────────────────────────┐
   管理者 ──HTTPS──► │  web (Next.js)  Vercel        │
                    │  /chat  /admin  /about        │
                    └──────────────┬───────────────┘
                                   │ SSE
                    ┌──────────────▼───────────────┐
                    │  api (FastAPI)  Fly.io        │
                    │  guardrail → retrieve →      │
                    │  rerank → prompt → LLM →     │
                    │  citation check → trace      │
                    └───┬──────────────┬───────────┘
                        │              │
        ┌───────────────▼──┐      ┌────▼──────────────────┐
        │ Postgres 16      │      │ LLM (OpenAI 兼容)      │
        │ + pgvector       │      │ DeepSeek / Qwen / 本地 │
        │ (Supabase)       │      └───────────────────────┘
        │ 文档 块 向量      │
        │ 会话 消息 日志    │
        │ 评测 run/item    │
        └──────────────────┘
```

一个 Postgres 装下：向量、业务数据、请求日志、评测结果。
**不引入独立向量库**——在十万块以内，pgvector 的 HNSW 足够，少一个服务就少一类故障。

## 技术选型

| 层 | 选型 | 为什么 | 备选 |
| --- | --- | --- | --- |
| 前端 | Next.js 15 + Tailwind + shadcn/ui | SSE 流式、免费托管、SEO/分享页方便 | SvelteKit |
| 后端 | FastAPI + Pydantic v2 | 与评测、嵌入同一 Python 栈；类型即文档 | Hono (TS) |

| 嵌入 | bge-small-zh-v1.5（512 维，CPU） | 免费、中文好、512 维省空间 | bge-m3、text-embedding-3-small |
| 生成 | DeepSeek-chat / Qwen-plus | 中文强、便宜；OpenAI 兼容好切换 | gpt-4o-mini、本地 Qwen |
| 重排 | bge-reranker-base（可选，E3 实验） | top-20 → top-5 精度提升 | Cohere Rerank |
| 观测 | 自建 `traces` 表 + JSON 日志 | 数据在自己库里，后台能直接查 | Langfuse（后期可选） |
| 评测 | 自建 harness + YAML 用例 | 完全可控、CI 可跑、结果入库可对比 | promptfoo、ragas |
| 部署 | Docker → Fly.io；GitHub Actions | 单镜像、环境一致 | Railway、Render |

## 一次请求的链路

1. **入口校验**：长度 ≤ 2k 字、限流（IP 20 次/小时）、会话 ID 合法。
2. **输入护栏**：正则命中危机词 → 熔断模板（不经检索、不调生成）；命中越权意图 → 拒答模板。
3. **查询处理**：口语 → 检索式（可选改写在 E5 实验）。多轮时拼接最近 2 轮上下文。
4. **检索**：pgvector HNSW，`cosine`，top-20，按文档版本过滤。
5. **重排**（可开关）：bge-reranker 取 top-5，分数落 trace。
6. **组装 prompt**：系统规则 + 5 个片段（带 `id` 与出处）+ 输出 JSON Schema。
7. **生成**：流式；同时累计 token。
8. **输出护栏**：引用 id 必须存在于命中集合，否则剔除；禁用词（诊断结论、药物名）过滤；缺引用则补「依据不足」提示。
9. **落库**：trace（耗时、token、成本、命中、护栏动作、引用）、消息（脱敏后）。
10. **流式返回**：`meta` → `delta`* → `citations` → `done{trace_id}`。

## API 契约

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/chat` | body: `{session_id?, message}`；返回 SSE |
| GET | `/api/sessions/{id}` | 回放会话（脱敏） |
| POST | `/api/feedback` | `{message_id, rating, comment?}` |
| GET | `/api/admin/overview?range=7d` | 用量、成本、延迟、拒答率、转介率、好评率 |
| GET | `/api/admin/traces/{id}` | 单次调试：查询、命中块与分数、prompt、原始响应、耗时 |
| GET | `/api/admin/evals` | run 列表与指标对比 |
| POST | `/api/admin/evals/run` | 触发评测（异步任务） |

管理端鉴权：v1 用 HTTP Basic + 环境变量口令，够用且零依赖。

## 可观测性

每条请求落一行 trace，后台按此出指标：

- **延迟**：retrieve / rerank / llm / total 的 p50、p95。
- **成本**：tokens_in/out、按模型单价折算 `cost_usd`，日/周聚合。
- **质量代理**：引用校验通过率、空引用率、拒答率、转介率、好评率。
- **检索**：命中块数量、最高分、平均分、无命中率（低于阈值 → 语料缺口信号）。
- **异常**：LLM 超时/5xx、JSON 解析失败、护栏误杀（人工标记）。

日志：stdout JSON（Fly 收集），`trace_id` 贯穿前后端；**不落原文到日志**，落库内容脱敏（邮箱、手机、身份证号）。

## 几个刻意的「不做」

- **不做多租户 / 组织 / SSO**：v1 单租户，公开演示 + 管理口令。
- **不做自研前端状态管理**：SSE + React state 足够。
- **不微服务化**：一个 API 容器，省掉服务发现与联调。
- **不做微调**：RAG 的瓶颈在检索与语料，不在模型权重。
